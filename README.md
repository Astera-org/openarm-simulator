# Openarm Simulator

Run your control code against a physically simulated OpenARM robot controlled through the DAMIAO motor CAN interface.

## Motivation

Robots are dangerous.
Before deploying control code you probably want to first see how it behaves in simulation. 
This project provides no guarantees but it does provide some signal.

## Production Readyness

Absolutely not.
Much of the code has been generated by LLMs under supervision.
Not all behavior has been compared to sufficient data from the real hardware.
The goal is to improve this over time, so we welcome contributions.

## HTTP and browser access

The HTTP API binds to `127.0.0.1:8080` by default. To allow a web client,
launch with `--allow-origin http://localhost:5173`. Repeat the flag for additional
origins (scheme, hostname, and port must match), or use `--allow-origin '*'` to
allow any origin. No cross-origin browser access is permitted by default.

Every API request must include `Content-Type: application/json`, including GET.
GET has no body; POST, PUT, and DELETE require valid JSON. Commands without
arguments (`/reset`, `/pause`, `/unpause`, and DELETE) take `{}`. Missing or
unsupported content types return 415; malformed JSON returns 400, and input
validation errors return 400 or 422. Successful commands may have no response
body. Error bodies may be JSON or plain text.

Request bodies are limited to 16 KiB, including chunked requests. A body that
stalls for two seconds is rejected before the command executes; this timeout
does not limit how long an accepted simulator operation can run.

```js
await fetch("http://127.0.0.1:8080/reset", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: "{}",
});
```

CORS [simple requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS#simple_requests),
including some POSTs, can reach a server without preflight approval; withholding
CORS response headers does not prevent their side effects. Requiring JSON rejects
those requests before executing commands and makes cross-origin browser clients
obtain preflight approval. OPTIONS preflights are bodyless, exempt from the JSON
requirement, and never execute commands. CORS is enforced by browsers, not native
clients; it is not authentication. Remotely hosted pages may also need the
browser's local-network permission.
